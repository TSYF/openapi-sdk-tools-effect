# @openapi-sdk-tools/effect

Optional [Effect](https://effect.website) integration for SDKs generated by
`openapi-sdk-tools`.

The package contributes two kernel capabilities:

| Export | Capability | Purpose |
| --- | --- | --- |
| `effectSchemaPlugin(schema, options?)` | `errorDecoder` | Decode raw SDK errors with an Effect Schema |
| `effectMatchPlugin(options?)` | `match` | Resolve SDK error handlers with an Effect Match resolver |
| `effectPlugin({ schema?, match? })` | both | Compose the two capabilities in one plugin |
| `toEffect(result)` | none | Convert any `SdkResultAsync` to an `Effect` |
| `effectClient(client)` | none | Wrap a result client so methods return `Effect` |

This package is **not a result backend**. It never provides the `result`
capability, never wraps values in an `EffectResult`, and never changes how
results are created or chained. Use `toEffect` / `effectClient` when you want
Effect-native consumption.

## Requirements

- **Peer dependencies**
  - `@openapi-sdk-tools/core` ^2.0.0
  - effect ^4.1.0 (Effect v4)
- **ESM-only.** The package is `"type": "module"`. Use
  `module`/`moduleResolution` of `nodenext` (or `node16`/`bundler`) and
  explicit `.js` extensions on relative imports.
- **Node.js >= 22.19.** Effect 4 documents 22.19+.
- **TypeScript >= 5.9** with `strict: true`, per Effect's requirements.

CommonJS consumers on Node >= 22.12 can load the package through `require(esm)`.
`require("@openapi-sdk-tools/effect")` returns the **ESM namespace itself**: named
properties and destructuring work, but there is no `default` export and no
`__esModule` marker. Node versions without `require(esm)` fail with
`ERR_REQUIRE_ESM`.

Effect v3 is not supported. The implementation uses Effect v4 APIs
(`Schema.decodeUnknownResult`, `Result`, `Match.value`, the v4 `Effect.promise`
signature).

## Install

```bash
pnpm add @openapi-sdk-tools/effect effect
```

`@openapi-sdk-tools/core` is already a dependency of the generated SDK, so it is
normally satisfied by the SDK itself.

## Registering the plugin

Plugins are client-level and resolved once per client; they are not per-call
options.

```ts
import { TicketResultClient } from "./sdk";
import { effectPlugin } from "@openapi-sdk-tools/effect";

const client = new TicketResultClient({
  baseUrl: "https://api.example.com",
  plugins: [effectPlugin({ schema: ApiError, match: true })],
});
```

Register at most one plugin per capability across the whole `plugins` array.

## Schema decoding

`effectSchemaPlugin(schema, options?)` decodes the raw error before the
client-level `errorMapper` and before matching. Only errors are decoded; success
responses are not validated.

```ts
import { Schema } from "effect";
import { effectSchemaPlugin } from "@openapi-sdk-tools/effect";

const ApiError = Schema.Struct({
  code: Schema.String,
  message: Schema.String,
});

type ApiErrorPayload = Schema.Schema.Type<typeof ApiError>;

const client = new TicketResultClient({
  baseUrl: "https://api.example.com",
  plugins: [
    effectSchemaPlugin(ApiError, {
      source: "body", // "auto" | "raw" | "body"
      onFailure: "raw", // "raw" | "error" | "throw"
      preserveStatus: true,
    }),
  ],
});

const message = await client.TicketController_getById(1).match(
  () => "ok",
  {
    NOT_FOUND: ({ error }) => {
      const apiError = error as ApiErrorPayload & { status?: number };
      return `${apiError.code}: ${apiError.message} (status ${apiError.status})`;
    },
    _: ({ error }) => String(error),
  },
);
```

The decoder supplies the runtime shape. Generated result clients type errors as
`unknown` by default, so annotate or cast when a handler needs the decoded
properties; `errorMapper` controls the client's static error type. The combined
`effectPlugin` example below infers the resolver type directly from the schema.

### Options

| Option | Default | Behavior |
| --- | --- | --- |
| `source` | `"auto"` | `"auto"` and `"body"` decode `raw.body` for an `HttpRequestError`; otherwise the raw value is decoded. `"raw"` always decodes the whole raw error. |
| `onFailure` | `"raw"` | `"raw"` returns the selected input unchanged. `"error"` returns the `Schema.SchemaError` as the decoded error value. `"throw"` throws it, rejecting the result promise. |
| `preserveStatus` | `true` | Attaches the HTTP status to a decoded object as a non-enumerable `status` property. Frozen or sealed values keep their own shape. |
| `parseOptions` | none | Forwarded to `Schema.decodeUnknownResult`. |

Decoding is synchronous because `ErrorDecoder.decode` is synchronous. Use
synchronous schemas only.

With the defaults, an invalid payload does not throw: the raw body flows into
matching and normally lands on `__SDK_UNDECLARED_ERROR__` or the `_` wildcard.

## Match resolution

`effectMatchPlugin(options?)` installs a `MatchStrategy` whose first step is your
resolver. A typical resolver uses Effect's own `Match`:

```ts
import { Match } from "effect";
import { effectMatchPlugin } from "@openapi-sdk-tools/effect";

const client = new TicketResultClient({
  baseUrl: "https://api.example.com",
  plugins: [
    effectMatchPlugin({
      resolve: (error) =>
        Match.value(error).pipe(
          Match.when({ _tag: "RateLimited" }, () => "RATE_LIMIT_EXCEEDED"),
          Match.when({ status: 404 }, () => "NOT_FOUND"),
          Match.orElse(() => undefined),
        ),
      discriminantKeys: [["body", "kind"]],
    }),
  ],
});
```

`resolve` receives the error and the kernel `MatchContext` (`declaredCodes`,
`discriminatorKey`). Returning `undefined` continues to the next step.

Resolution order:

1. `resolve(error, context)`
2. the client `errorDiscriminatorKey` path
3. the `_tag` field (Effect convention)
4. each extra `discriminantKeys` path
5. HTTP status through `STATUS_TO_CODE_MAP`, scoped to the operation's declared
   codes
6. `__SDK_UNDECLARED_ERROR__`, when a handler exists
7. the `_` wildcard

Only codes declared by the operation select a specific handler. A resolver
result that is not declared falls through instead of jumping to the wildcard.
Resolver hits report `metadata.source = "discriminator"` with
`metadata.discriminant` set to the code.

There is no declarative `patterns` map; use the `resolve` callback.

## Combined plugin

`effectPlugin` attaches only the capabilities you request. Type the resolver
through the schema: `TError` is inferred from `schema`, so `match.resolve`
receives the decoded error type.

```ts
import { Schema } from "effect";
import { effectPlugin } from "@openapi-sdk-tools/effect";

const ApiError = Schema.Struct({
  code: Schema.String,
  message: Schema.String,
});

const client = new TicketResultClient({
  baseUrl: "https://api.example.com",
  plugins: [
    effectPlugin({
      schema: ApiError,
      schemaOptions: { onFailure: "raw", preserveStatus: true },
      match: {
        resolve: (error) => error.code, // typed as the decoded ApiError
      },
    }),
  ],
});
```

At least one of `schema` or `match` must be enabled. `effectPlugin({})` throws a
configuration error. Passing only `schema` uses the default match strategy;
passing only `match` disables error decoding.

## Consuming results as Effects

`toEffect` works with any `SdkResultAsync`, regardless of the registered result
backend. It reads the outcome through `.match()`.

```ts
import { Effect } from "effect";
import { toEffect } from "@openapi-sdk-tools/effect";

const client = new TicketResultClient({ baseUrl: "https://api.example.com" });

const program = Effect.gen(function* () {
  const tickets = yield* toEffect(client.TicketController_getAll({}));
  return tickets.length;
});

const count = await Effect.runPromise(program);
```

`effectClient` wraps a result-returning client so every `SdkResultAsync` return
becomes an `Effect`, including nested sub-clients. Non-result methods, arrays,
and plain values pass through unchanged; methods stay bound to the original
client.

```ts
import { Effect } from "effect";
import { effectClient } from "@openapi-sdk-tools/effect";

const effectApi = effectClient(
  new TicketResultClient({ baseUrl: "https://api.example.com" }),
);

const program = Effect.gen(function* () {
  const tickets = yield* effectApi.TicketController_getAll({});
  return tickets.length;
});

await Effect.runPromise(program);
```

Root clients work too: `effectClient(new AgendaShopResult(options))` wraps
`client.ticket`, `client.reserva`, and the other nested clients.

## What this package does not do

- No `ResultBackend`; results keep using the core default or another backend
  such as `@openapi-sdk-tools/neverthrow`.
- No `EffectResult` wrapper around `SdkResultAsync`.
- No success-response schema decoding or validation.
- No Effect v3 support.
- No declarative `patterns` map for matching.
- No changes to `core`, `generator`, `nestjs`, or generated SDK output.

## API

```ts
effectSchemaPlugin(schema, options?): SdkPlugin
effectSchemaDecoder(schema, options?): EffectSchemaDecoder<T>

effectMatchPlugin(options?): SdkPlugin
effectMatchStrategy(options?): MatchStrategy

effectPlugin({ schema?, schemaOptions?, match? }): SdkPlugin

toEffect(sdkResult): Effect.Effect<T, E>
effectClient(client): EffectClient<T>
```

Types: `EffectSchemaOptions`, `EffectMatchOptions`, `EffectSchemaDecoder`,
`EffectPluginConfig`, `EffectClient`.
